(a) Redefine $\mathrm{high}(x)=\lfloor x/u^{2/3}\rfloor$, $\mathrm{low}(x)=x\bmod u^{2/3}$ and $\mathrm{index}(i,j)=iu^{2/3}+j$; the summary has universe $u^{1/3}$ and each cluster $u^{2/3}$. The code of @prp-veb-successor and @prp-veb-insert is otherwise unchanged: each operation still makes at most one recursive call that does real work, either on the summary (size $u^{1/3}$) or on a cluster (size $u^{2/3}$). In the worst case the call is on a cluster, so $T(u)=T(u^{2/3})+O(1)$. With $m=\lg u$, $S(m)=S(\frac23m)+O(1)=O(\log_{3/2}m)$, so all three operations still take $O(\lg\lg u)$ time, with a larger constant ($\log_{3/2}2\approx1.71$ times as many levels). Space is $O(u)$ as before.

(b) Now a structure holding one element stores it as min = max, and one holding two elements stores them as min and max, with no recursive content. *Successor:* if $x<V.\min$ return min; if $x\ge V.\max$ return none; otherwise search the clusters as before, and if nothing larger is found there, return $V.\max$. *Insert:* if $x<\min$ swap $x$ with min; if $x>\max$ swap $x$ with max; then insert the displaced element into its cluster as before (empty clusters cost $O(1)$, with the summary call). *Delete:* deleting min or max must pull the new min (or max) out of the recursive structure, found in $O(1)$ through the summary's min (max) and that cluster's min (max), followed by a recursive delete from that cluster, plus a summary delete only when the cluster becomes empty, which then makes the cluster call $O(1)$. In all cases there is still one non-trivial recursive call: the running times stay $O(\lg\lg u)$. The gain is a constant factor (two-element structures need no recursion), at the price of more cases in the code.
:::
